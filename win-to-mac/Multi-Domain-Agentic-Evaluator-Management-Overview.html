Management Overview · Frontier Engineering Programme

Teaching our AI to grade our AI

A proposal to build an agentic evaluator that automates capstone assessment across four technology tracks — RAG, multi-agent AI, secure tool integration (MCP), and the final integrated system.

Companion to: Multi-Domain Agentic Evaluator — Design Document (v4.0) · Rev 1.0

01Executive summary

Every cohort produces capstones across four tracks, currently graded entirely by hand. We propose an agentic evaluator — a system of specialised AI agents — to make grading faster, more consistent, and able to scale, without removing human judgement from the process.

02The problem

  • Manual review does not scale — grading time grows with cohort size, coaching time does not.
  • Grading quality varies with which facilitator reviews a submission, and how much time they have.
  • Some failure modes are genuinely hard to catch by reading code — e.g. confirming a safety rule can't be talked around by rephrasing a request.
  • Security boundaries need to be actively tested, not just reviewed on paper.

03Three levels of rigour

Each track is assessed at up to three increasing levels. Each level is a complete, usable system on its own — building Level 1 does not commit us to Level 2 or 3.

1

Static review

Reading the brochure before buying a car

Reads the submitted code and report; checks the required pieces are present and genuinely complete.

2

Live execution

Taking the car for a test drive

Actually runs the system in a safe, isolated environment and tests it with real scenarios.

Adversarial stress-test

Sending a mystery shopper

Deliberately tries to break it — trick questions, unauthorised access attempts, edge cases.

05Why Nexus is different

Nexus isn't a new technology to check — it tests whether the other three tracks were genuinely connected together in one live system. Its own grading brief says it plainly: "integration, not reimplementation."

New checkWhat it verifies
Integration tracerFollows one real request end-to-end and confirms each stage's output genuinely feeds the next stage's input
Guardrails checkerConfirms the full safety stack is active across the whole system, not just one component
Anti-decomposition checkTests for a team having "gamed" the integration requirement with a shortcut that merely looks wired together

Everything else is reused directly from the other three tracks' evaluators — which is why Nexus's module is one of the cheapest to add, provided the other three already exist.

06What stays human

  • Final grading decisions always stay human — the system produces evidence and a proposed score, not an unappealable verdict.
  • Live demo communication skills are not something we're trying to automate away.
  • Anything the system is unsure about, or that fails a safety/security check, is automatically routed to a person.
  • Safety-sensitive test content is authored and reviewed by someone with appropriate clinical/safeguarding background.

09Risks and how we manage them

RiskMitigation
Level 1 trusts a claim it can't verifyEvery finding is confidence-tagged; unverified items are flagged for a human, never silently scored as correct
Generated test questions feel inconsistent across submissionsAll questions anchored to the same published bank; only the specific example varies, never the difficulty
Safety-sensitive test contentAuthored/reviewed by someone with clinical or safeguarding background; clearly labelled synthetic
Running learner code introduces security exposureIsolated, disposable environment with no unnecessary network access
System over-trusts its own stress-test resultsAny single safety/security failure is an automatic hard-stop for human review, regardless of the rest of the score

10Recommendation

  1. Start with Phase 1 — shared foundation plus Level 1 review across RAG, Multi-Agent, and MCP. Lowest cost, lowest risk entry point.
  2. Run it alongside manual grading for one cohort before relying on it, to build confidence and calibrate against real facilitator decisions.
  3. Add the Nexus module last, only after the other three tracks are complete — its low cost depends directly on that order.
  4. Revisit scope after each phase with real data, rather than committing to the full build up front.

11Glossary

RAG
Retrieval-Augmented Generation — an AI system that retrieves relevant information, then generates a response grounded in it.
MCP
Model Context Protocol — a standard way for AI systems to connect securely to external tools and data, instead of custom integrations per system.
Agent
A focused, single-purpose AI component responsible for one task, e.g. checking a report section or verifying a security rule.
Level (1/2/3)
The three increasing levels of evaluation rigour: static review, live execution, adversarial stress-testing.
Escalation
A rule that hands a decision to a human instead of letting the AI resolve it automatically — used both inside the capstones being graded, and inside the evaluator itself.
Rubric
The published set of weighted criteria a capstone submission is graded against.
Sandbox
An isolated, disposable environment used to safely run a learner's submitted code.
