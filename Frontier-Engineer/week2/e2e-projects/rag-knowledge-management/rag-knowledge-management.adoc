== 1. Project Overview

This project is an end-to-end **Retrieval-Augmented Generation (RAG)** application called **Company Knowledge Assistant**. It allows employees to ask natural-language questions about internal company documents — such as policies, FAQs, guides, handbooks, and announcements — and receive accurate, grounded answers generated by an LLM.

The system follows a complete RAG pipeline:

1. **Ingestion** — Load documents from the `data/` directory, chunk them, generate embeddings, and store them in a PostgreSQL + pgvector vector database.
2. **Retrieval** — For a given user question, perform semantic (vector) search to retrieve the most relevant document chunks.
3. **Reranking** — Rerank retrieved chunks using Cohere's reranking model to improve precision.
4. **Generation** — Pass the top-ranked chunks as context to an LLM (GPT-4o-mini) to generate a grounded answer.
5. **Caching** — Cache LLM responses using Redis Semantic Cache to avoid redundant API calls for semantically similar questions.

The system also includes a **RAGAS evaluation** script to quantitatively measure the quality of the RAG pipeline using metrics like faithfulness, answer relevancy, context precision, and context recall.

== 3. File-by-File Explanation

=== 3.1 `docker-compose.yml`

Defines three Docker services orchestrated together:

- **postgres** (`pgvector/pgvector:pg17`):
  - PostgreSQL 17 pre-installed with the `pgvector` extension for vector storage.
  - Mounts `init-db/` to `/docker-entrypoint-initdb.d/` so `init.sql` runs automatically on first start.
  - Has a health check using `pg_isready`.

- **app**: 
  - Built from the `Dockerfile` in the same directory.
  - Runs the FastAPI application via Uvicorn on port 8000.
  - Depends on PostgreSQL being healthy before starting.
  - Mounts the project directory into `/app` for hot-reloading during development.
  - Has a health check via `/health` endpoint.

- **redis** (`redis/redis-stack:latest`):
  - Redis Stack with RedisJSON, RediSearch, RedisTimeSeries modules.
  - Port 6379 for Redis, port 8001 for RedisInsight GUI.
  - Used for semantic caching of LLM responses.
  - Append-only persistence enabled.

Two named volumes (`pgdata`, `redis-data`) persist database and cache data across container restarts.

=== 3.2 `Dockerfile`

Multi-stage build using `python:3.11-slim`:

- Installs system dependencies: `build-essential`, `curl`, `ca-certificates`.
- Sets `WORKDIR` to `/app`.
- Copies and installs Python packages from `requirements.txt` (layered for caching).
- Copies the `app/` and `data/` directories.
- Exposes port 8000.
- Default CMD: `uvicorn app.api:app --host 0.0.0.0 --port 8000 --reload`.

NOTE: The `requirements.txt` file is referenced by the Dockerfile but is currently missing from the repository. You would need to create it with the necessary dependencies (see the Dependencies section below).

=== 3.4 `app/api.py` — FastAPI Application

The main web server with the following endpoints:

==== `GET /`
Serves the static `index.html` frontend page.

==== `POST /ingest`
Starts document ingestion as a **background async task**.

- Uses an `asyncio.Lock` to prevent concurrent ingestion jobs.
- Returns HTTP 409 if ingestion is already running.
- The background job updates a shared `_ingest_last` dict tracking status (`idle`, `running`, `succeeded`, `failed`), timestamps, statistics, and error messages.

==== `GET /ingest/status`
Returns the current state of the ingestion process (status, stats, timestamps, error info).

==== `POST /ask`
Accepts a JSON body `{"question": "..."}` and runs the full RAG pipeline:

1. Calls `answer_with_docs_async()`.
2. By default filters results to the `"guides"` category (hard-coded but easy to change).
3. Returns `{answer, sources, contexts}`.

The application also:
- Mounts static files at `/static`.
- Logs execution time for each `/ask` request.

=== 3.5 `app/ingest.py` — Document Ingestion Pipeline

The ingestion process follows these steps:

==== Step 1: Load Documents (`_load_docs()`)
- Recursively scans the `DATA_DIR` directory for supported file types.
- Uses category-specific loaders from LangChain community:
  - `.md` → `UnstructuredMarkdownLoader`
  - `.pdf` → `PyMuPDFLoader`
  - `.docx` → `UnstructuredWordDocumentLoader`
  - `.txt` → `TextLoader`
- Tags each document with a `category` metadata field derived from its parent folder name (e.g., `data/guides/file.md` → `category="guides"`).
- Skips directories and hidden files.
- Errors on individual files are caught and logged without stopping the pipeline.

==== Step 2: Chunk Documents (`_chunk()`)
- Uses `RecursiveCharacterTextSplitter` from LangChain.
- `chunk_size=900` characters per chunk.
- `chunk_overlap=120` characters between consecutive chunks to maintain context continuity.

==== Step 3: Store Embeddings
- Connects to the PostgreSQL vector store via `get_vector_store()`.
- Generates embeddings for each chunk using OpenAI's `text-embedding-3-small`.
- Asynchronously stores the embeddings + metadata in the `langchain_pg_embedding` table.

==== Step 4: Create Vector Index (`_create_index()`)
- Creates an **HNSW** (Hierarchical Navigable Small World) index for efficient approximate nearest-neighbor search.
- Uses **cosine distance** as the similarity metric.
- Configuration: `m=16` (connections per node), `ef_construction=64` (index quality).

The function returns a dict with `{documents: N, chunks: N}` statistics.

=== 3.6 `app/rag.py` — RAG Retrieval + Generation Chain

==== System Prompt
The LLM is instructed to:
- Answer strictly based on the provided context.
- Reply "I don't know" if the answer is not in the context.
- Prefer the most recent policy by effective date when conflicts exist.

==== Chain Construction (`_build_chain()`)

1. **Vector Store** — Connect to PostgreSQL vector store.
2. **Retriever** — Configured with:
   - `k=5` documents retrieved (configurable via `RETRIEVAL_K` env var).
   - Optional metadata filter by category (e.g., only search "guides").
3. **Reranker** — Uses Cohere `rerank-multilingual-v3.0` to reorder the 5 retrieved chunks, keeping the top 3 (`top_n=3`). This improves retrieval precision.
4. **LLM** — OpenAI `gpt-4o-mini` for cost-effective, fast generation.
5. **Chain** — Uses LangChain's `create_stuff_documents_chain` (stuff all context into prompt) wrapped by `create_retrieval_chain`.

==== Semantic Caching
- Uses `RedisSemanticCache` with:
  - Redis URL from `REDIS_URL` env var.
  - Same embedding model (`text-embedding-3-small`) for cache key generation.
  - `distance_threshold=0.98` — semantically similar questions (within 0.98 cosine similarity) return cached responses.
- This reduces API costs and latency for repeated or similar questions.

==== `answer_with_docs_async()`
- Builds the chain, invokes it asynchronously with the user's question.
- Extracts and returns:
  - `answer` — The generated text.
  - `sources` — Unique source file paths from retrieved documents.
  - `contexts` — Full text content of the retrieved chunks.

=== 3.7 `app/utils.py` — Database & Vector Store Setup

- Reads `DATABASE_URL` from environment.
- Creates a `PGEngine` (from `langchain_postgres`) for managing the PostgreSQL connection.
- Initializes OpenAI embeddings model (`text-embedding-3-small`, 1536 dimensions).
- `get_vector_store()` creates and returns an `AsyncPGVectorStore` configured with:
  - `table_name="langchain_pg_embedding"` — the vector storage table.
  - `metadata_json_column="langchain_metadata"` — JSON metadata column.
  - `metadata_columns=["category"]` — allows filtering searches by category.

=== 3.8 `app/eval_ragas.py` — RAGAS Evaluation

A script that evaluates the RAG system's quality using the **RAGAS** framework:

- Loads test Q&A pairs from `seed/qna_test.json`.
- For each question, sends a POST to `http://localhost:8000/ask` and captures the answer and retrieved contexts.
- Creates `SingleTurnSample` objects with: `user_input`, `response`, `retrieved_contexts`, `reference`.
- Evaluates using four RAGAS metrics:
  - **Faithfulness** — Is the answer factually consistent with the retrieved context?
  - **Answer Relevancy** — How relevant is the answer to the question?
  - **Context Precision** — How relevant are the retrieved documents to the question?
  - **Context Recall** — Are all relevant documents retrieved?
- Outputs per-question scores and averages.

=== 3.9 `app/static/index.html` — Frontend UI

A clean, single-page HTML application with:

- A header showing the brand name and an **"Ingest Data"** button with status pill.
- A text area for entering questions (supports `Ctrl+Enter` / `Cmd+Enter` shortcut).
- **"Ask"** and **"Clear"** buttons.
- An answer display area with source document links.
- JavaScript that:
  - Calls `/ingest` (POST) to trigger document ingestion.
  - Polls `/ingest/status` every 2 seconds to update the status pill.
  - Calls `/ask` (POST) with the user's question.
  - Renders the answer and sources in the UI.

=== 3.11 `init-db/init.sql`

PostgreSQL initialization script that runs automatically when the Postgres container starts for the first time:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS langchain_pg_embedding (
    langchain_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    content text,
    embedding vector(1536),
    langchain_metadata jsonb,
    category text
);
```

- Enables the `vector` extension (required by pgvector).
- Creates the `langchain_pg_embedding` table with:
  - `langchain_id` — UUID primary key.
  - `content` — The raw text of the chunk.
  - `embedding` — 1536-dimensional vector (OpenAI `text-embedding-3-small` dimension).
  - `langchain_metadata` — JSONB for flexible metadata.
  - `category` — Direct column (also indexed via metadata_columns in LangChain).

== 4. How to Execute the Project

=== 4.1 Prerequisites

- Docker and Docker Compose installed.
- An OpenAI API key (set in `.env`).
- (Optional) A Cohere API key (set in `.env` for reranking).
- (Optional) LangSmith API key (set in `.env` for tracing).

=== 4.2 One-Command Start (Docker — Recommended)

```bash
# Clone and navigate to the project
cd Frontier-Engineer/week2/e2e-projects/rag-knowledge-management

# Create requirements.txt if missing (see Dependencies section below)

# Start all services
docker compose up --build
```

This starts three containers:
- `cka-db` — PostgreSQL with pgvector on port 5432.
- `cka-redis` — Redis Stack on port 6379 (GUI on 8001).
- `cka-app` — FastAPI app on http://localhost:8000.

**First-time setup:** The database initialization is automatic — `init-db/init.sql` runs when `cka-db` starts for the first time.

=== 4.3 Step-by-Step Manual Execution

If you want to run without Docker (e.g., using your local PostgreSQL):

Step 1: **Create and activate a Python virtual environment**

```bash
python3 -m venv venv_rag
source venv_rag/bin/activate
```

Step 2: **Install dependencies**

Create a `requirements.txt` file with these packages:

```txt
fastapi==0.115.6
uvicorn[standard]==0.34.0
langchain==0.3.17
langchain-openai==0.3.4
langchain-community==0.3.16
langchain-postgres==0.0.14
langchain-redis==0.0.4
langchain-cohere==0.3.4
langchain-classic==0.0.6
pypdf==5.1.0
pymupdf==1.25.2
unstructured==0.16.14
python-docx==1.1.2
openai==1.59.6
psycopg2-binary==2.9.10
asyncpg==0.30.0
redis==5.2.1
cohere==5.12.7
ragas==0.2.7
pandas==2.2.3
httpx==0.28.1
python-multipart==0.0.19
```

Then install:

```bash
pip install -r requirements.txt
```

Step 3: **Set up PostgreSQL with pgvector**

If running locally (not Docker), you need PostgreSQL with the pgvector extension:

```bash
# On macOS with Homebrew:
brew install postgresql@17 pgvector

# Start PostgreSQL
brew services start postgresql@17

# Create the vector extension
psql -U postgres -c "CREATE EXTENSION IF NOT EXISTS vector;"

# Create the embeddings table
psql -U postgres -d postgres -f init-db/init.sql
```

Update the `.env` file's `DATABASE_URL` to point to your local PostgreSQL:

```
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/postgres
REDIS_URL=redis://localhost:6379/0
```

Step 4: **Start Redis** (for semantic caching)

```bash
# With Docker
docker run -d --name redis-stack -p 6379:6379 -p 8001:8001 redis/redis-stack:latest

# OR with Homebrew
brew install redis
brew services start redis
```

Step 5: **Run the application**

```bash
uvicorn app.api:app --host 0.0.0.0 --port 8000 --reload
```

Step 6: **Open the UI**

Navigate to http://localhost:8000 in your browser.

Step 7: **Ingest documents**

Click the **"Ingest Data"** button in the UI, or send a POST request:

```bash
curl -X POST http://localhost:8000/ingest
```

Check status:

```bash
curl http://localhost:8000/ingest/status
```

Step 8: **Ask questions**

Type a question in the UI and click **"Ask"**, or use the API:

```bash
curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "What is the VPN policy?"}'
```

== 7. Key Design Decisions

1. **Async everywhere** — All I/O operations (DB queries, API calls, file loading) are asynchronous using `asyncio`, ensuring the server remains responsive under concurrent requests.

2. **Background ingestion** — Document ingestion runs as a background task, so the API remains available during processing. A lock prevents concurrent ingestion jobs.

3. **Metadata filtering** — Documents are categorized by source folder, enabling filtered retrieval by category (e.g., only search "policies" or "guides").

4. **Reranking** — Using Cohere's reranker after initial vector retrieval improves precision by re-ranking the top-k results, ensuring only the most relevant contexts are fed to the LLM.

5. **Semantic caching** — Redis Semantic Cache avoids redundant LLM calls for semantically similar questions, reducing both cost and latency.

6. **Category-based retrieval** — The `/ask` endpoint currently hard-codes `category="guides"`, demonstrating filtered search. This can be parameterized for production use.

7. **Evaluation framework** — RAGAS integration allows quantitative measurement of RAG quality, essential for iterating on the pipeline.
